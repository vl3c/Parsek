# Forensics: slot 0 lost its Re-Fly affordance (session 2026-09-08_2317_refly-a-manual)

Worktree: `Parsek-refly-continuation` @ `c3d844ebe`. Session: `logs/2026-09-08_2317_refly-a-manual/`.
All `KSP.log:N` citations are line numbers in that folder's `KSP.log` (28889 lines).

## Summary

**This is a DEFECT, not design, and it is NOT a regression from any merge after 2026-08-20.**
The terminal stamping is correct and is what the design wants: the scene-exit ballistic
extrapolator predicted an impact for the still-alive sub-orbital pod, stamped
`terminal=Destroyed`, and `TerminalKindClassifier` maps `Destroyed -> Crashed -> the slot
stays re-flyable`. The raw classifier agreed: `IsUnfinishedFlight=true rec=32ca5546
reason=crashed` (`KSP.log:17434`), and the commit promoted slot 0 to `CommittedProvisional`
(`KSP.log:17435`). The slot was OPEN and correct at that instant.

What closed it is an ordering defect inside a single commit. `MergeDialog.MergeCommit` runs
`CommitPendingTree()` (which promotes the slot's effective tip) and only THEN
`RecordingStore.RunOptimizationPass()`
(`Source/Parsek/MergeDialog.Commit.cs:82` then `:86`). 230 ms after the promotion the
optimizer's phase-change split cut the promoted recording at UT 191.04 into HEAD `32ca5546`
(272 pts) plus a brand-new chain TIP `8da7c2c2` (129 pts) that carries the terminal
(`KSP.log:17549`, `KSP.log:17561`, `KSP.log:17563`).
`RecordingOptimizer.TransferTerminalFieldsToSecondHalf`
(`Source/Parsek/RecordingOptimizer.cs:1323`) moves the terminal to the tip
(`:1367-1368`) but does NOT move `MergeState`, and `Recording.MergeState` defaults to
`Immutable` (`Source/Parsek/Recording.cs:331`). Open/closed is read from the TIP
(`UnfinishedFlightClassifier.IsSlotEffectiveTipOpen`,
`Source/Parsek/UnfinishedFlightClassifier.cs:849-865`), so the slot silently closed:
`IsUnfinishedFlight=false rec=32ca5546 reason=sealedTipClosed rp=... slot=0`
(`KSP.log:18207`). At the next commit the first-commit guard cemented it:
`CommitTree: rec=8da7c2c2 already committed/fork - not re-deriving MergeState (slot=0 ...)`
(`KSP.log:22012`). The reaper reads the same tip predicate and deleted the RP quicksave for
good (`KSP.log:24025`).

No causal commit after 2026-08-20. The two halves of the mechanism landed 2026-05-21
(`76f479af0` / `91d48e921`, PR #942, the "collapse Seal into MergeState" change that made the
tip's `MergeState` the single open/closed source) and predate that on the optimizer side.
The interaction between optimizer phase-change splits and Re-Fly slots is a known family
(`e1783ce09`, 2026-05-18, "Dedupe STASH group by chain so optimizer phase-change splits
don't double Re-Fly slots"); this is the un-fixed member of it.

**Proposed fix (smallest):** in `RecordingOptimizer.TransferTerminalFieldsToSecondHalf`
(`RecordingOptimizer.cs:1323`), beside the terminal move at `:1367-1368`, carry the
open/closed bit with it: `second.MergeState = original.MergeState;`. The open bit is
terminal-keyed by construction, so it must travel with the terminal. Mirror direction
(required by CLAUDE.md): `RecordingOptimizer.MergeInto` (`:744`) carries
`absorbed.TerminalStateValue` onto `target` but likewise not the `MergeState`, so absorbing
an open tip into an `Immutable` head has the identical failure; take the more-open of the
two there. Nothing about the extrapolated tail changes, so rendering is untouched.

### 1b. The slot's MERGE STATE: a Destroyed terminal is supposed to keep the slot OPEN

`Source/Parsek/TerminalKindClassifier.cs:41-42` maps `Destroyed -> TerminalKind.Crashed`, and
the type's own doc comment states the rule: "Crashed - destroyed / BG-crash. Merge rule
commits `MergeState.CommittedProvisional` so the slot stays rewindable (design 6.6 step 2,
7.17, 7.43)." The research doc repeats it twice for exactly this shape:

- `extending-rewind-to-stable-leaves.md:276` -- "Crashed booster (S2) ... terminal Destroyed
  -> qualifies regardless of isFocus -> CP. RP stays alive."
- `:511` -- "Survivor crashes anyway. V's chain TIP terminal Destroyed (Crashed). Crashed
  always qualifies regardless of focus -> CP -> UF row."

This matters because `focusSlot=0` (`KSP.log:16189`): slot 0 WAS the focus slot. Had the
finalizer stamped `SubOrbital` instead, the focus-slot gate would have excluded it and the
operator would have needed a manual Stash. The `Destroyed` stamp is what made it qualify
automatically. **So the predicted-impact terminal is the operator's friend here, not the
defect.** The runtime agreed: `KSP.log:17434`
`IsUnfinishedFlight=true rec=32ca5546 reason=crashed terminal=Destroyed side=active-parent-child`,
followed by `KSP.log:17435`
`CommitTree promoted rec=32ca5546 ... slot=0 rp=rp_a9967... reason=crashed to CommittedProvisional`.

Design authority for open/closed: `docs/parsek-rewind-to-separation-design.md:101` -- "A
slot's open/closed state is the slot's effective chain+supersede tip recording's MergeState:
CommittedProvisional is open ..., Immutable is closed. This is the single source of truth."

## 3. THE DEFECT

### 3a. The wrong decision, stated precisely

**`RecordingOptimizer.SplitAtSection` moves a recording's terminal to the new chain TIP but
leaves the TIP's `MergeState` at its `Immutable` default, and open/closed is read from the
TIP. A split therefore silently closes any Re-Fly slot whose origin recording it cuts.**

Full causal chain, all within one commit plus the next:

1. **23:11:22.046** `KSP.log:17434-17435`. `RecordingStore.ApplyRewindProvisionalMergeStates`
   (`RecordingStore.cs:1173-1302`) resolves slot 0, `TryQualify` returns `crashed`, and the
   HEAD-demotion branch (`:1258-1267`) sets `32ca5546.MergeState = CommittedProvisional`.
   The chain-tip branch (`:1282-1296`) is a no-op because at this instant
   `slot.EffectiveRecordingId(supersedes) == rec.RecordingId` -- the recording is unsplit
   (400 points, `KSP.log:16852`). **Correct at this instant.** Confirmed: the log contains
   ZERO `CommitTree promoted chain-tip` lines.
2. **23:11:22.270-.279** `KSP.log:17549`, `:17561`, `:17562`, `:17563`.
   `MergeDialog.MergeCommit` reaches `RecordingStore.RunOptimizationPass()`
   (`MergeDialog.Commit.cs:86`, four lines after `CommitPendingTree()` at `:82`). The split
   predicate accepts a `PersistedPhaseChange` boundary at `sec=7 splitUT=191.04
   prev=Atmospheric next=ExoBallistic` and cuts:
   `SplitAtSection: split 32ca5546... at UT=191.0 (first: 272 pts/7 sections, second: 129 pts/7 sections)`,
   then `ReindexChain: chainId=1848a736..., 2 branch-0 members re-indexed`.
   `RecordingOptimizer.TransferTerminalFieldsToSecondHalf`
   (`RecordingOptimizer.cs:1323`, called at `:1236`) moves the terminal:
   ```
   1367:            second.TerminalStateValue = original.TerminalStateValue;
   1368:            original.TerminalStateValue = null;
   ```
   `MergeState` appears **zero times** in the whole of `RecordingOptimizer.cs`, so the new
   tip takes `Recording.MergeState`'s field initializer, `MergeState.Immutable`
   (`Recording.cs:331`). The persisted save proves it: `8da7c2c2` has
   `chainIndex = 1`, `pointCount = 129`, `terminalState = 4` (Destroyed) and **no
   `mergeState` key at all**, while `32ca5546` has `chainIndex = 0`, `pointCount = 272`,
   `mergeState = CommittedProvisional`. The codec omits the key exactly when the value is
   `Immutable` (`RecordingTreeRecordCodec.cs:446-447`) and reads a missing key back as
   `Immutable` (`:868-871`).
3. **23:11:26.012** `KSP.log:18207`. `IsSlotEffectiveTipOpen`
   (`UnfinishedFlightClassifier.cs:849-865`) resolves the slot tip through
   `ChildSlot.EffectiveRecordingId` -> `EffectiveState.EffectiveTipRecordingId`
   (`ChildSlot.cs:128-131`, the composite chain+supersede walker), gets `8da7c2c2`, reads
   `Immutable`, returns false. `EffectiveState.cs:1064` emits `sealedTipClosed`. The STASH
   row is gone.
4. **23:13:57.664** `KSP.log:22012`. On the second commit the tip branch DOES now reach
   `8da7c2c2` -- and the first-commit guard (`RecordingStore.cs:1204-1207`, `:1288`) refuses:
   `CommitTree: rec=8da7c2c2... already committed/fork - not re-deriving MergeState (slot=0 rp=rp_a9967...)`.
   The guard exists to stop a deliberately sealed tip being re-opened. Here it cements an
   `Immutable` nobody ever chose. **Second lock, not first cause** -- removing the guard
   would be the wrong fix.
5. **23:14:00.441** `KSP.log:24025-24026`. `RewindPointReaper.IsReapEligible`
   (`RewindPointReaper.cs:209-228`) reads the same tip `MergeState`, finds every slot closed,
   reaps the RP and deletes the quicksave. Irreversible.

Why slot 1 survived: `d096297d` was never split (final save shows `pointCount = 108`, no
`chainId`), so its tip is itself, still `CommittedProvisional`, and
`CanInvokeSlot: slot-ok ... slot=1` (`KSP.log:18217`).

### 3b. The smallest fix

Keep the extrapolated tail exactly as it is (rendering, orbit segments, terminal UT all
unchanged) and carry the open bit with the terminal it is keyed to.

In `Source/Parsek/RecordingOptimizer.cs`, `TransferTerminalFieldsToSecondHalf` (`:1323`),
beside `:1367-1368`:

```csharp
// Open/closed for a Re-Fly slot is read from the slot's effective chain TIP
// (UnfinishedFlightClassifier.IsSlotEffectiveTipOpen), and this method has just
// made `second` that tip by moving the terminal onto it. The open bit is
// terminal-keyed, so it must travel with the terminal; leaving `second` at
// Recording.MergeState's Immutable default silently closes the slot and the
// reaper then deletes its RP.
second.MergeState = original.MergeState;
```

Copying rather than moving is deliberate: a stale `CommittedProvisional` on the HEAD is inert
(`TryQualify` accepts `Immutable` OR `CommittedProvisional` --
`UnfinishedFlightClassifier.cs:44-50` -- and every open/closed read goes through the tip).
The stricter variant, mirroring the terminal move exactly
(`original.MergeState = MergeState.Immutable;` after the copy), is also safe -- a split HEAD
retains its chain link, so it can never be any slot's forward tip -- but it changes more
state than the bug requires.

Cost check on the first-commit guard: with the fix, step 4's `already committed/fork` line
still fires, but the tip is already `CommittedProvisional`, so it correctly changes nothing.
The guard's own regression tests
(`CollapseSealMergeStateRegressionTests.cs:191/:345/:920`) are unaffected.

Blast radius on the harness: the fix emits no new log token. GS-1 forbids the literal
`CommitTree promoted rec=` (spec `:790-792`), which this fix does not produce -- the
alternative fix of re-running the promotion after `RunOptimizationPass()` WOULD produce it,
which is one more reason to prefer this one.

### 3c. Mirror direction (required check)

`RecordingOptimizer.MergeInto` (`:744`) is the inverse operation and has the identical
asymmetry: it forwards the terminal (`target.StampTerminalState(absorbed.TerminalStateValue,
"RecordingOptimizer.AbsorbInto")`) but never touches `MergeState`, so absorbing an OPEN
(`CommittedProvisional`) tip into an `Immutable` head yields an `Immutable` survivor and
closes the slot the same way. Today this is masked because the promotion at
`RecordingStore.cs:1258` and `:1290` sets BOTH the head and the tip to
`CommittedProvisional`; it would be exposed the moment a tip is open while its head is not
(exactly the shape plan section 4.2 describes for a continuation tip with no branch-linked
head). The merge side should take the more-open of the two:

```csharp
if (absorbed.MergeState == MergeState.CommittedProvisional
    && target.MergeState == MergeState.Immutable)
    target.MergeState = MergeState.CommittedProvisional;
```
