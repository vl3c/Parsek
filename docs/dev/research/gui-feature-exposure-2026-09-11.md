# Parsek feature-exposure matrix

What the backend can do, and how the player reaches it.

Source of truth: `C:/Users/vlad3/Documents/Code/Parsek/Parsek-gui-census-dump` at
`9e145cca4` (origin/main merged 2026-09-11). Read-only pass; nothing was built, flown
or edited. Every `file:line` is relative to the repo root.

Sibling agent owns the GUI surface inventory (layouts, controls, windows). This
document names the entry point only far enough to identify it, and spends its budget
on the backend side of each row.

## Classes used

| Class | Meaning |
|---|---|
| EXPOSED | A player-facing control reaches the capability. |
| AUTOMATIC | The capability runs without any control. The Notes column says whether the player is told (ScreenMessage, dialog, a changed label) or whether it is silent. |
| HIDDEN | Real backend capability with no player entry point. Sub-kinds: `hidden-setting` (field exists, no UI, often clamped at load), `seam-only` (reachable only through the M-A2 harness command seam in `Source/Parsek/TestCommands/`), `retired` (surface deliberately withdrawn), `unexposed` (never had a surface). |
| PROMISED-NOT-DELIVERED | A control, label, tooltip or shipped doc claims something the handler does not do. |
| DEAD | A control whose handler is unreachable or a no-op. |

### The five Re-Fly preconditions, and whether each refusal reaches the player

All five are evaluated in `RewindInvoker.EvaluateCanInvoke` (`RewindInvoker.cs:71`), cached 60s (`:4256`). Every reason string is returned to the caller, and both hosts put it in the disabled Fly button's tooltip, which `DisabledHoverEcho` publishes to the window help strip. So all five ARE shown, with these caveats:

1. Scene transition in progress (`:83`) -> "Scene transition in progress - please wait". Shown.
2. RP marked Corrupted (`:97`) -> "Rewind point is marked corrupted". Shown, but the reason it BECAME corrupted is not: `MarkCorrupted` (`:4400`) permanently flips `rp.Corrupted`, so the original "Missing parts: X, Y" text is replaced by the generic corrupted string on every later frame.
3. Quicksave missing on disk (`:109`) -> "Quicksave file missing on disk: {name}". Shown. This precondition races `SweepMissingRewindPointQuicksaves`, which on the next load force-seals the slot instead (`LoadTimeSweep.cs:359`) and removes the button entirely.
4. Another re-fly session active (`:117`) -> "Another re-fly session is already active". Shown. Plus a context-level twin at `:92`.
5. Deep-parse PartLoader check (`:122`, impl `:4316`) -> "Missing parts: ...", "Quicksave file failed to parse", "Quicksave parse threw: ...". Shown on the first evaluation only (see 2).

Two visibility gaps: in the Timeline's **Re-Fly tab**, `HasActionableFlyOrSealButton` (`UI/TimelineWindowUI.cs:1580`) filters out any row whose route is not `Resolved`, so a "Rewind point slot not found" row is invisible there rather than disabled-with-reason (it still renders disabled in Overview/Details). And `ShowDialog` re-checks nothing; post-confirm refusals come from `StartInvoke` and are toasted (`RewindInvoker.cs:828`).
